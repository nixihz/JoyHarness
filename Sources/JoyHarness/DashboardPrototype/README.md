# Dashboard UI 原型（throwaway）

问题：控制器成为主视觉之后，多少映射信息值得常驻？

在仓库根目录运行 `task prototype`，打开 <http://localhost:8769/dashboard?variant=B>。
不依赖第三方包，也可直接执行 `python3 Sources/JoyHarness/DashboardPrototype/serve.py`。
底部箭头或键盘左右键切换 A/B/C，地址中的 `variant` 可复制、刷新保留。
原型位于 Dashboard 源文件旁边；项目是原生 SwiftUI，没有可复用的浏览器路由。
因此 `/dashboard` 是独立预览服务器中的页面，不是新增的产品路由。

## 三个方向

| 方案 | 常驻结构 | 适合的问题 |
| --- | --- | --- |
| A 控制器聚焦 | 顶部连接与模式 → 大设备图 → 单次输入 → 详情入口 | 用户能否迅速确认控制器可用，并理解当前输入？ |
| B 映射对照 | 顶部摘要 → 设备与逐项按键对照 → 输入反馈 | 熟悉按键时，能否少开一次设置？ |
| C 紧凑工具窗 | 小设备图与摘要 → 输入反馈 → 可展开的按键参考 | 日常使用能否占用更少屏幕空间？ |

用户倾向 B，本轮沿 B 细化：设备与逐项映射并排，下方链路状态默认展开且可收起。
保留控制器、适配器、运行模式、权限、语音、录音归属、四种震动测试与设置/版本入口。
控制器不支持震动不等于链路异常；能力未知和不可用分开显示。正式 SwiftUI 页面尚未采用原型。

## 设计约束

1. 目标：用户看清设备连接、运行模式、权限限制，找到映射设置入口。
2. 范围：Dashboard 控制器概览；连接详情按需打开。Settings 只预览原生窗口的信息结构。
3. 层级：设备与状态是主要信息；完整映射和能力明细是次要信息；输入读数是反馈。
4. 视觉重点：复用控制器 PNG；青色只用于输入，绿色用于已连接，橙色用于权限限制。
5. 状态：未连接给出蓝牙/USB 指引；扫描进入等待；读取失败允许重试；权限受限就近说明；原生模式明确暂停映射；未知能力不填充为成功或 0。
6. 文案：中文/英文共享结构；长状态换行，内容可滚动，窄屏对照区改为纵向。
7. 复用：系统字体、4/8/12/16/22/32 间距、7px 组件圆角、既有控制器资源。浏览器语义色近似 macOS，正式实现应还原系统颜色和原生控件。

没有任务列表、任务状态、任务标题或槽位展示。
“上一个槽位”等仅作为已有映射动作的名称出现，不包含关联任务信息。

## 交互与数据

- 小米的按键名称、动作、电量与权限摘要取自运行窗口的只读快照（2026-09-19）；适配器、语音和录音归属补自用户截图。
- 其他设备的映射来自 `ControllerMappingStore.defaultMappings` 和 `ControllerInput.availableInputs`，不是已连接设备的声明；设备名称遵循 `displayName`。
- 顶部可选择八类设备、七种场景、三种外观和两种语言。场景与非小米设备的能力均为明确标识的模拟。
- 点击控制器上的按键或按键参考，显示物理输入和已配置动作；Space / Enter 同样可用。
- 原生模式保持物理输入预览，动作显示“映射已暂停”；断开和设备切换清除输入状态。
- 配置按键打开只读 Settings 结构预览；权限动作打开原型指引，不改真实设置。
- 扫描只进入“正在连接”场景，后续结果由顶部场景选择器决定，不虚构连接成功。
- 状态只存在内存，页面下方可展开完整相关状态。无存储、无硬件调用、无真实映射执行。
- `Package.swift` 明确排除此目录，原型及切换条不会进入 Debug/Release 应用资源。

## 验证记录

- 已验证三方案切换、URL 更新和刷新保留方案。
- 已验证按键点击、释放、原生模式暂停、断开、重新扫描和权限指引。
- 已检查亮色英文 C、深色 A/B、高对比窄屏（460px）排版。
- 语义文本颜色与三种背景的最低对比度：深色 6.86:1、亮色 4.91:1、高对比 9.25:1。

## B 第二轮：多设备与完整链路

| 设备 | 图解与输入差异 | 能力呈现 |
| --- | --- | --- |
| 小米遥控器 | 纵向遥控器、12 个输入 | 保留用户截图里的麦克风与适配器状态；震动不可用；不展示不适用的扳机 |
| DualSense | 既有透明图、PlayStation 按键、触控板、功能层 | 自适应扳机、声音输入入口、震动测试 |
| DualShock | 无专属资产，退回控制器符号 | 触控板、标准扳机、震动测试 |
| Xbox | 既有图、A/B/X/Y、LT 功能层 | 无触控板、Impulse Trigger 示例能力 |
| Joy-Con L / R | 单只图；横握/竖握改变图片和肩键名称 | 单个端点、握持方向、体感；只保留该设备可配置的 16 个输入 |
| Joy-Con L + R | 两只图并排；B/A/Y/X 与 ZL 功能层 | 逻辑组合、左右端点分别显示；无触控板 |
| 通用控制器 | 控制器符号，无厂商图形假设 | 无法确认的能力显示未知，震动测试禁用 |

B 的基础按键/功能层使用原生 select，全部输入独立列出，可在固定高度内滚动。
握持方向使用原生 radio；原生 SwiftUI 实现时使用 segmented Picker。
Joy-Con 图不添加未经校准的热点，点击右侧按键参考可以预览输入。
链路内容在主区域下方，桌面双列分组、窄屏纵向排列；避免恢复三栏常驻诊断侧栏。
震动测试在原型中只显示反馈类型，不访问硬件。已验证可用、不可用和未知三种启用状态。

本轮验证：八种设备资源均可显示；单只 Joy-Con 9 个基础输入 / 7 个功能层输入；横握肩键改为 SL/SR；震动可用、不可用、未知状态均正确启停；模拟原生模式后仍保持功能层选择且映射暂停；断开清除高亮并禁用震动。浏览器无 JavaScript 错误。
