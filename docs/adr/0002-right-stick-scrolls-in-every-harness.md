# 右摇杆在所有 Harness 中直接滚动

不按 LT 时，右摇杆直接滚动网页和文档，所有 Harness 都一样，包括 Codex。Codex 径向输入只保留十字键左/下/右这一个入口。

**状态**：accepted（2026-09-25）

## 背景

- 以前滚动要按住 LT 再推左摇杆。
- 右摇杆（不按 LT）只发送 Codex 径向输入。在 Claude、Cursor、Antigravity、Pi 下它完全闲置，见 [K01](../controller-mappings.md#k01-非-codex-harness-下右摇杆不按-lt完全闲置)。
- 把手柄当鼠标用时，最常见的布局是“左摇杆移动指针、右摇杆滚动”，不需要修饰键。只有单摇杆设备才需要“修饰键 + 摇杆”滚动。

## 决策

- **右摇杆（不按 LT）**：在所有 Harness 中滚动。
  - 方向跟随设置里的“自然 / 传统”。
  - 速度曲线与 LT + 左摇杆相同。
  - 可以和左摇杆移动指针同时进行。
- **Codex 径向输入**：不再读右摇杆，只保留十字键左/下/右（默认映射，可改）。
- **LT + 左摇杆滚动**：保留。单只 Joy-Con 只有一个摇杆，只能靠它滚动；对双摇杆手柄也不冲突。
- **LT + 右摇杆四个方向**：仍然是快捷方向（默认左/右为网页上一页/下一页）。按住 LT 时右摇杆不滚动。
- 右摇杆滚动是固定行为，不进映射表。

## 考虑过的方案

- **只在非 Codex Harness 下滚动，Codex 保留右摇杆径向输入**：同一个摇杆在不同 Harness 下含义不同，切换 Harness 后容易误操作；Codex 下仍然只能按 LT 滚动。
- **把右摇杆四个方向开放为可映射输入**：能解决闲置，但滚动需要连续的模拟量，四个离散方向做不好滚动；也要新增映射项和迁移。
- **维持现状**：滚动要双手配合按 LT，和常见手柄布局不一致。

## 取舍

- Codex 失去右摇杆的连续径向输入（任意角度 + 力度）。十字键只能发 8 个方向、力度固定为 1。
- 需要细粒度径向输入的用户没有替代入口。如果以后确实需要，可以新增一个可选开关，让 Codex 下的右摇杆恢复为径向输入。

## 影响

- `ButtonBridge.rightStickHandler` 发送右摇杆位置；按住 LT、切换到原生模式、重置时归零。切换浮层打开期间，`JoyHarnessMain` 也会停止滚动。
- `ControllerHub` 按会话汇总右摇杆，和左摇杆一样处理多手柄同时连接的情况。
- `MouseBridge` 的运动引擎拆成指针和滚动两个通道，共用同一个时钟，所以指针和滚动可以同时进行。
- `RightStickScrollTests` 覆盖以下几点：
  - 右摇杆滚动，不再发送径向输入；
  - 按住 LT 时改为快捷方向；
  - 十字键仍发送径向输入；
  - 重置后停止滚动；
  - 两种滚动的速度一致；
  - 滚动方向设置对右摇杆生效。
