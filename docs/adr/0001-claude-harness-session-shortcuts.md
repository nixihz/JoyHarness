# Claude Harness 默认使用会话切换与搜索快捷键

Claude Harness 的肩键和右扳机默认发送 Claude Desktop “Go” 菜单的三个快捷键：

| 按键 | 快捷键 | Claude Desktop 菜单项 |
|---|---|---|
| L1 / LB | `⌘⇧[` | 上一个会话 |
| R1 / RB | `⌘⇧]` | 下一个会话 |
| RT / R2 | `⌘⇧K` | 搜索 |

已保存的 Claude 配置里，这些键如果仍是“不执行操作”，会一次性补上新默认值。补过之后，用户再改回“不执行操作”也不会被覆盖。

**状态**：accepted（2026-09-25）

## 背景

- Codex 用 L1/R1 切换任务槽，用 RT 聚焦 Codex，三者都走 Codex Micro。
- 非 Codex Harness 屏蔽 Codex Micro 输入，所以 Claude 下这三个最顺手的键全是空的。
- Claude Desktop 同时开很多会话，最常用的操作恰好是前后切换会话和搜索会话。
- 选用这组快捷键，可以沿用 Codex 的肌肉记忆：肩键负责“上一个 / 下一个”，RT 负责“跳过去”。

## 决策

- **默认值**：`defaultMappings(for:provider:)` 只对 Claude 叠加这三项，并且只写入该控制器家族实际有的输入。
  - 单只 Joy-Con 只有 L1/R1，写成 SL/SR（竖握为 L/ZL 或 ZR/R）。
  - 小米遥控器也只有 L1/R1，对应音量 −/+。
  - RT 保持为空。
- **迁移范围**：迁移按配置执行，即“控制器家族 × Harness”，标记为 `<配置存储键>.claudeSessionDefaultsMigrated`。
- **迁移时机**：
  - 初始化；
  - 切换控制器家族或 Harness；
  - 运行时读取某个家族的映射，覆盖“已连接但不是设置页当前选中的家族”这种情况。
- **迁移规则**：只把存储值为“不执行操作”的键补成新默认值；已自定义为其他动作的键保持不变。

## 与不变量的取舍

[CONTEXT.md](../../CONTEXT.md) 要求“自定义映射在产品升级后保持不变，除非用户主动重置或修改”。

问题在于，存储里的“不执行操作”有两种可能的来源：

- 旧版本的默认值；
- 用户刻意设置的。

两者无法区分。我们按“旧默认值”处理，并且只处理一次。

**可接受的原因**：Harness 切换功能尚未正式发布，只写在 Unreleased 里。已保存的 Claude 配置只可能来自开发版本，刻意设成“不执行操作”的情况极少。

**代价**：真这样设过的用户，升级后需要再改回一次。之后迁移标记生效，不会再次覆盖。

## 考虑过的方案

- **只改默认值，不迁移**：开发版里已保存的 Claude 配置会一直是空键。用户看不到新功能，除非手动执行“恢复默认映射”，而这会把其他自定义一起清掉。
- **迁移时覆盖所有值**：会覆盖用户已自定义的其他动作，直接违反上面的不变量。
- **改用其他键位**：
  - 十字键左/右在 Claude 下虽然空着，但在 Codex 中是径向输入。用肩键承担“上一个 / 下一个”，两个 Harness 的语义才一致。
  - Menu 在 Codex 中用于按住说话，用作会话切换同样会破坏这种一致性。

## 影响

- `ControllerMappingProviderTests` 覆盖以下几点：
  - 默认值；
  - 只迁移一次；
  - 不覆盖自定义；
  - 运行时读取未选中的家族时也会迁移。
- 以后给其他 Harness（Cursor、Antigravity、Pi）补默认值时，可以复用“按配置一次性补空键”的迁移方式。
- 届时需要新写一篇 ADR 引用本文，并重新评估当时的发布状态：功能已正式发布后，“不执行操作”更可能是用户刻意设置的。
