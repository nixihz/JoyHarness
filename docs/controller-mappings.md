# 控制器默认映射与测试清单

> 更新：2026-09-25
>
> 本文列出所有已支持的控制器、所有 Harness 的出厂默认映射，以及不能改键的固定行为。
> 用途有三个：对照实机测试、记录用着不顺手的地方、决定调整后关联到对应的 ADR。

## 怎么读这份文档

- **真值来源**：
  - 默认映射来自 `ControllerMappingStore.defaultMappings(for:provider:)`，见 [ControllerMapping.swift](../Sources/JoyHarness/ControllerMapping.swift)。
  - 按键名称来自 `ControllerInput.displayName`。
  - 代码里的默认值改了，这里要一起改。
- **自定义优先**：表中是“恢复默认映射”后的行为，自定义映射会覆盖默认值。测试前，先在“设置 → 按键映射”里对当前 Harness 和控制器执行“恢复默认映射”。
- **分开保存**：映射按“Harness × 控制器配置”分开保存。
  - Xbox、DualSense、DualShock、通用手柄共用一份配置（`controllerMappings.v1`），见 [K10](#k10-标准手柄四个家族共用一份映射)。
  - Joy-Con Pair、Joy-Con L、Joy-Con R、小米遥控器各自一份（`controllerMappings.v1.profiles.<家族>`）。
  - 非 Codex Harness 在键名后追加 `.providers.<harness>`；Codex 沿用升级前的键名。
- **测试标记**：☐ 是勾选位。反馈问题时引用编号，例如 `P03`、`J11`。
- **“无”**：表示默认“不执行操作”。按下后，前台 App 不应收到任何按键，Codex Micro 也不应收到输入。
- **权限**：键盘、鼠标、文本输入类动作都需要“辅助功能”权限。

## Harness

| Harness | 关联应用 bundle ID | 能否向 Codex Micro 发送 |
|---|---|---|
| Codex | `com.openai.codex` | 能 |
| Claude | `com.anthropic.claudefordesktop` | 不能 |
| Cursor | `com.todesktop.230313mzl4w4u92` | 不能 |
| Antigravity | `com.google.antigravity` | 不能 |

**非 Codex 的默认值怎么来**

- 从 Codex 默认值出发，去掉 Codex 专属动作：批准、拒绝、按住说话、聚焦 Codex、槽位、径向输入。
- Claude 在此基础上补上会话切换和搜索，原因见 [ADR 0001](adr/0001-claude-harness-session-shortcuts.md)。
- Cursor、Antigravity 的默认值完全相同，下文合并为一列。

**Codex Micro 输入的限制**

- 按下只在两个条件同时满足时发送：当前 Harness 是 Codex，且切换浮层已关闭。
- 松开和归零不受限制，照常发送。
- 所以在非 Codex Harness 里把某个键手动设为“批准”这类 Codex 动作，设置会保存，但运行时不会发送。

## 动作实际发出什么

| 动作 | 实际发出 | 按住不放时 |
|---|---|---|
| 鼠标左键 / 右键 / 中键 | 鼠标按下，松开按键时释放，可拖拽 | 保持按下 |
| 按住加速鼠标 | 按住期间指针使用“快速”灵敏度（默认 `1.8x`） | 保持加速 |
| 退格 | Delete | 按系统节奏重复 |
| ↑ ↓ ← → 方向键 | 方向键 | 按系统节奏重复 |
| 回车 | Return | 不重复 |
| Esc | Escape | 不重复 |
| 右侧 Command | 右 ⌘ 按下，松开时释放，带右侧设备标志，供按住说话类语音工具识别 | 保持按下 |
| 复制 / 粘贴 | `⌘C` / `⌘V` | 不重复 |
| 飞书截图 | `⌘⇧A` | 不重复 |
| 网页上一页 / 下一页 | `⌘[` / `⌘]` | 不重复 |
| 上一个 / 下一个 Claude 会话 | `⌘⇧[` / `⌘⇧]` | 不重复 |
| Claude 搜索 | `⌘⇧K` | 不重复 |
| 输入 yes / no | 直接输入文本 `yes` / `no`，不按回车 | 不重复 |
| 批准 / 拒绝 | Codex Micro `ACT07` / `ACT08` | — |
| 按住说话 | Codex Micro `ACT10`，按下 / 松开 | 保持按下 |
| 聚焦 Codex | Codex Micro `ACT12` | — |
| 上一个 / 下一个槽位 | `AG00`–`AG05`，6 个槽位首尾循环；震动 1–6 下提示槽号 | — |
| 选择槽位 1–6 | `AG00`–`AG05` | — |
| Codex 径向输入 | `v.oai.rad`，角度 + 力度 | 持续发送 |
| 切换原生/映射模式 | 切换所有已连接控制器的工作模式 | — |

还有两个可选的 Codex 动作，没有默认键位：快速模式（`ACT06`）和拆分线程（`ACT09`）。

## 单只 Joy-Con

单只 Joy-Con 没有 LT/RT、十字键、右摇杆、R3 和 Home。肩键名称随握持方向变化，下表写作“横握名（竖握名）”。

**功能层没有默认修饰键。** 要使用下表的功能层部分（J11–J18），先在设置里把以下任一键设为“LT 功能层与滚动”：

- 肩键：Joy-Con L 为 SL/SR（竖握 L/ZL），Joy-Con R 为 SL/SR（竖握 ZR/R）
- 摇杆按下
- − 或 +
- Capture 或 Home

## 已知问题 / 待调整

每项写明现象、影响和调整建议。决定调整后：

- 如果这个决定难以回退、没有上下文会让人意外、并且确实有取舍，就新增一篇 ADR，并在该项后面注明 ADR 编号。
- 纯文案或标签修正不需要 ADR。

### K01 非 Codex Harness 下，右摇杆（不按 LT）完全闲置

- **状态**：已解决，见 [ADR 0002](adr/0002-right-stick-scrolls-in-every-harness.md)。右摇杆在所有 Harness 中直接滚动（`F03`），Codex 径向输入只保留十字键（`P05`）。原来的 `P06` 已删除。
- **现象**：不按 LT 时，右摇杆只发送 Codex 径向输入。映射表里也没有“右摇杆”这一项，无法自定义。
- **影响**：Claude、Cursor、Antigravity 下，手柄上最顺手的模拟输入之一白白浪费。
- **建议**：在非 Codex Harness 下让右摇杆负责滚动（左摇杆指针、右摇杆滚动是常见布局），或把右摇杆四个方向开放为可映射输入。

### K02 Cursor、Antigravity 大量键位默认为空

- **现象**：Menu、RT、LB/RB、十字键左/下/右、LT+A/B、LT+LB/RB、LT+十字键四向，共 15 个键默认为“无”。Claude 补上 LB/RB/RT 后仍有 12 个为空。
- **影响**：切换到这些 Harness 后，大半个手柄没有反应（`P01`–`P10`）。
- **建议**：逐个 App 核实真实快捷键后再填，不凭印象猜。Claude 的候选项包括权限确认/拒绝（LT+A/B）、新建会话等，均待核实。

### K03 单只 Joy-Con 默认用不了功能层和滚动

- **现象**：
  - 单只 Joy-Con 没有默认功能层键，`J11`–`J18` 默认都按不出来，包括摇杆滚动。
  - 设置界面的功能层名称固定为 “ZL + …” / “ZR + …”；竖握时会出现 “ZL + ZL”、“ZR + ZR” 这类让人困惑的名称。
- **影响**：单手使用时缺少批准、拒绝、yes/no、复制和滚动。
- **建议**：
  - 给单只 Joy-Con 指定一个默认功能层键。
  - 让功能层名称显示实际选中的修饰键。

### K04 单只 Joy-Con 无法呼出 Harness 切换浮层

- **现象**：
  - Joy-Con R 的 Home 被当作 Options 映射为飞书截图（`J08`）。
  - Joy-Con L 本身没有 Home 键。
  - 横握时，物理 L/ZL、R/ZR 键不参与映射。
- **影响**：只用单只 Joy-Con 时无法切换 Harness，只能靠前台 App 自动匹配。
- **建议**：让 Joy-Con R 的 Home 与游戏手柄保持一致，改为呼出切换浮层，并把飞书截图移到其他键；或新增可映射的“Harness 切换”动作。

### K05 小米遥控器无法呼出切换浮层

- **现象**：主页键为 Esc，菜单键为原生/映射切换，没有任何键能呼出浮层。浮层由手柄呼出后，遥控器可以操作（`H07`）。
- **影响**：只有遥控器在手时，无法手动切换 Harness。
- **建议**：长按主页键呼出浮层，或新增可映射的“Harness 切换”动作，与 K04 一并处理。

### K06 游戏手柄没有默认的“进入原生模式”入口

- **现象**：
  - 手柄 Home / PS 固定用于切换浮层，它存储的“切换原生/映射模式”不再生效；设置界面显示为“Harness 切换”。
  - 要进入原生模式，只能靠白名单 App 自动切换、小米遥控器菜单键，或自己把某个键设为“切换原生/映射模式”。
- **影响**：在非白名单游戏里用手柄时，需要先改映射。
- **建议**：在切换浮层中加一张“原生模式”卡片，并清理 Home 的遗留存储值。

### K07 DualSense / DualShock 触控板按键与 × 重复

- **现象**：触控板按键和 × 默认都是鼠标左键（`G10`）。
- **影响**：浪费了一个大面积按键。
- **建议**：Codex 下改为按住说话（README 已把它列为可选入口）；其他 Harness 另选高频动作。

### K08 LT + 右摇杆 上/下 在所有 Harness 中都为空

- **现象**：只有左、右两个方向有默认动作（网页上一页/下一页）（`G19`）。
- **影响**：两个容易按到的组合键闲置。
- **建议**：候选项包括切换标签页（`⌃⇧Tab` / `⌃Tab`）、切换同一 App 的窗口（``⌘` ``），按 Harness 核实后再定。

### K09 飞书截图 `⌘⇧A` 是所有 Harness 和遥控器的默认键

- **现象**：飞书没运行或没设这个快捷键时，`⌘⇧A` 会发给前台 App（`G06`、`J08`、`X04`）。
- **影响**：可能误触发前台 App 自己的 `⌘⇧A` 命令。
- **建议**：发送前检测飞书是否在运行；或把默认值改为 macOS 自带截图 `⌘⇧5`，飞书截图作为可选动作。

### K10 标准手柄四个家族共用一份映射

- **现象**：Xbox、DualSense、DualShock、通用手柄读写同一个存储键。在 DualSense 上改的键位，会同时改到 Xbox。
- **影响**：
  - 两种手柄混用时无法各自定制。
  - [CONTEXT.md](../CONTEXT.md) 写的是“每个 Harness 与控制器家族的组合保留独立映射”，目前只有 Joy-Con 和小米遥控器做到了。
- **建议**：二选一，这是需要 ADR 的决定：
  - 按家族拆分：需要迁移，把旧值复制到每个家族。
  - 修正 CONTEXT.md：明确“标准手柄共用一份映射”。

### K11 DualShock 4 的 Share 键显示为 Create

- **现象**：DualShock 4 的实体键叫 Share，设置界面沿用了 DualSense 的名称 Create。
- **影响**：只影响标签，对照测试时容易找错键。
- **建议**：DualShock 单独显示为 Share。这是标签修正，不需要 ADR。
