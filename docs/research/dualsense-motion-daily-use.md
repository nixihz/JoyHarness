### 用户实测后的校准修订（2026-10-17）

用户反馈四方向录制反复失败，希望只识别相对参考的大致方向。代码回归复现了三处门槛：一致的录制样本可能生成仅 8° 的方向容差；0.4 秒的录制会把后续 L2 总按住时间限制到 0.62 秒；流程要求 15 次录制，并要求六次测试全对后才能应用。没有用户原始轨迹，不能认定每次失败的具体原因。

修订后的交互是：普通 L2 按放一次，四个方向各录一次；失败立即提示，某个方向可单独重录，其他参考保留。参考齐全且可区分即可应用，测试仅用于试手感和查看结果。新校准按最近方向匹配，默认方向容差 70°、候选余量 0.03，允许总按住 5 秒；幅度和速度主要根据普通按放噪声设门槛，不要求复现示范的力度和节奏。仍拒绝没有明确方向、普通轻晃、明显冲突及无效数据；这些数值是本轮实现参数，不是实测准确率或最优参数的承诺。已有配置的手动参数保持不变，重新录制并应用后使用新建议值。

快移单独使用 L2 按下 0.55、松开 0.1 的滞回，避免手指略微放松便把一次动作拆成多条录制；现有功能层阈值不变。真实手感与长期效率仍需使用者验证。

本轮验证：`swift test --no-parallel` 共 509 项测试通过，包含方向偏离 30°、较慢较小动作、按住前后停顿、五步生成、单项补录、取消补录保留草稿和 L2 滞回回归。通过项目脚本重新安装 `/Applications/Joy Harness.app`，签名、打包资源和启动检查通过；实际设置界面已核对“录制 1 / 5”和可选测试说明。没有代录用户个人动作，也未测量真实四方向准确率。

## 一、研究结论

**DualSense 体感在技术上可以接入，但现有证据不足以把“体感鼠标”作为 Joy Harness 的核心新功能。** 本机蓝牙传感器读取已经成功；真正未解决的是：相比现有摇杆、触控板、按键和语音，它能否降低日常操作成本。

本次调查的桌面与非游戏产品中，可借鉴的用途集中在三种任务：**远离桌面时指示对象；在明确状态中短暂调整连续参数；为特定用户提供另一种输入途径。** 它们通常配有清楚的启停、目标反馈和确认动作。仅增加“摇一下”“歪一下”的快捷方式，不能自然转化为效率提升。

现在最明确的产品切入点来自维护者的实际操作困难：**从屏幕一侧移到远处目标区域，摇杆移动时间过长。** “L2 按住、斜向甩动、松开定位到四个象限中心”把任务拆成一次大范围定位和后续小范围微调。它有明确的触发边界、有限目标和现有操作补充关系，值得优先做针对性验证；这一判断来自需求的具体性，并不代表识别效果已经验证。

除此之外，“用户离开键盘与 AI 交流时，怎样表达我说的是这里”仍是值得研究的方向。体感可能帮助指向或圈定，但完整价值来自可见目标、语音和上下文传递；触控板也可能获得同样收益，不能将整条交互链的价值都归于陀螺仪。

本报告建议：**优先围绕已明确的四象限定位需求验证交互，通用体感鼠标保留为比较基线。** 全局摇晃快捷键、自动判断用户意图，以及精确空间定位，不适合作为当前推进方向。后续方案应保留已有自定义映射，不能直接覆盖 L2 功能层。

### 已明确需求：L2 体感四象限定位

**需求来源：维护者在本次会话中明确描述。** 按下 L2 记录基准，向左上、右上、左下或右下甩动，松开时光标落到对应区域中心，随后用原有鼠标控制微调。产品名称可用“体感快速定位”。

这里的“中心点”按屏幕四个象限的中心解释，而不是显示器的四个边角。以下坐标以目标显示器左上角为原点：

| 左上区域 | 右上区域 |
| --- | --- |
| 中心：宽 25%、高 25% | 中心：宽 75%、高 25% |
| **左下区域**：宽 25%、高 75% | **右下区域**：宽 75%、高 75% |

**一次操作的完整过程：**

1. L2 进入按下状态时，记录本次参考起点和光标所在显示器；尚不移动光标。
2. 持续按住 L2，识别一次清楚的斜向主运动，保存目标象限。
3. 松开 L2 后，若本次仍有效，只执行一次定位；没有明确方向则不移动。
4. 后续摇杆、触控板与点击沿用原有行为，完成附近目标的精确操作。

**收益假设：** 长距离定位先变成一次固定落点的跳转，再完成剩余距离。识别只需确定四个方向，对连续轨迹精度的要求较低；实际收益要计入按住、甩动、松开和修正的总时间，不能只比较跳转本身。

#### 与现有 L2 行为共存的建议规则

当前 L2 在约 0.55 行程进入功能层；L2＋左摇杆滚动，L2＋右摇杆及面键还有其他动作。建议将定位定义为“本轮 L2 没有被其他输入使用时”的释放操作，而不是替换整套功能层。[ButtonBridge](../../Sources/JoyHarness/ButtonBridge.swift)

| 情况 | 建议行为 |
| --- | --- |
| 只按下、松开 L2；轻微抖动或方向模糊 | 不跳转，保留原功能层行为 |
| 使用了 L2 组合键、有效摇杆输入或触控板 | 执行原操作，取消本轮定位资格；松开不能再附带跳转 |
| 开始前或过程中按住鼠标键，包括其他输入设备 | 本轮取消，避免把拖拽对象带到另一处 |
| 打开 Harness 浮层、切原生模式、换 Harness、断连或数据中断 | 清除参考和候选，恢复后必须重新按下，不能补执行 |
| 用户已自定义 L2 为其他动作 | 不隐式叠加；具体启用配置属于后续实施方案 |
| 多显示器 | 锁定按下 L2 时光标所在屏幕；本轮不跨显示器，布局变化则取消 |

上述兼容规则已落实到当前开发版。多显示器按各显示器的 `CGDisplayBounds` 计算四个落点，使用与 `CGEvent` 一致的坐标；不能把所有屏幕合成的大矩形四等分，否则落点可能位于屏幕空隙。[MouseBridge](../../Sources/JoyHarness/MouseBridge.swift)

#### 方向识别中最重要的两个区别

**甩出的方向与松开时的姿态要分开。** 人甩出后往往自然回弹；若只看松开瞬间的角度或角速度，可能丢掉目标，甚至判断成反方向。应观察主运动段，锁存明确候选，再由 L2 松开提交。正常回弹不改选；第二次明显冲突的动作可保守取消，避免猜测目标。

**取基准与传感器校准要分开。** L2 按下记录的是本次相对参考，不代表当场消除了静止偏差。轻转手腕可研究短时间角速度积分；纯平移甩动可能只有加速度，识别路径不同。需采集自然持握下的实际动作，核对轴向、回弹、幅度与持续时间，不能把某一帧原始传感器正负直接当成屏幕方向，也不预设未经验证的阈值。

首轮可以用简单方向或落点标记验证是否容易理解，识别期间不驱动系统光标。大面积分区遮罩、声音、持续振动均不是这条需求的必要部分；如实现视觉反馈，应遵循现有 [DESIGN.md](../../DESIGN.md)。

#### 针对这条需求的验证重点

- 四个方向都能在自然坐姿下识别；甩出回弹后再松开，仍到原目标象限。
- L2 单独按放、轻微抖动、模糊或冲突动作不产生跳转。
- L2 组合键、滚动、触控板、拖拽和模式切换均不会留下待执行跳转。
- 对相同远距离目标，比较“现有摇杆含 L3 加速”“触控板/摇杆组合”“四象限定位后微调”的总时间和修正次数。
- 多显示器、负坐标屏幕、断连和显示器布局变化不会造成错误落点。

上述结果尚未实测。研究优先级提高的依据是新增了明确的日常任务缺口，不是已经证明体感更快。

#### 可调阈值与个人手势校准

**维护者已明确要求：** 用户能够调整阈值、测试能否定位，并录制左上、右上、左下、右下的个人动作，由应用建议适合自己的参数，调试后保存为默认。以下流程已按用户对首版的反馈修订。

**设置入口与信息层级。** 建议放在现有“设置 → 通用”的鼠标设置附近，增加“体感快速定位”分组，不为这一个功能新增顶层侧边栏。分组显示启用状态、当前配置来源（内置推荐 / 个人校准 / 手动调整）、“录制我的手势”和“测试”入口。当前 [鼠标灵敏度设置](../../Sources/JoyHarness/AppSettingsView.swift) 调整的是指针移动倍率；快移的判定阈值单独保存，调手势不能连带改变摇杆速度。

普通界面提供“触发灵敏度”的直观调节：偏向小动作时更容易触发，偏向大动作时更能排除轻晃；它以已校准的参数为基础，不代表所有判定条件只有一个数。高级设置可展开以下参数并说明影响，数值范围和初始值由真实动作验证后确定，不预先编造推荐角度或速度。

| 判定参数 | 解决的问题 | 调整时应提示的取舍 |
| --- | --- | --- |
| 最小动作幅度 | 普通按 L2 的晃动不能算甩动 | 太小容易误触；太大需要过分转腕或经常漏识别 |
| 动作速度与持续时间范围 | 区分有意的主运动与慢漂、瞬时毛刺 | 过严会拒绝用户舒适的小动作，不能一味要求猛甩 |
| 方向容差及候选间隔 | 决定动作是否足够接近某个方向且不易与相邻方向混淆 | 过宽容易串方向，过窄会增加“不确定”；必须允许不识别 |

L2 本身的按压触发阈值、传感器静止偏差与上述手势参数分别管理；不能通过调手势灵敏度偷偷改变功能层何时开启。

**当前录制流程：**

1. **准备。** 确认目标手柄正在提供有效体感数据；用当前自然坐姿握持，短暂稳定后记录噪声与偏差参考。录制的是传感器轨迹和 L2 时序，不需要摄像头或屏幕录像。每次 L2 按下仍重新定义局部参考。
2. **记录不应触发的动作。** 先做一次正常 L2 按放，记录按压造成的轻晃，作为“不要定位”的参考，用来区分有意动作与自然晃动。
3. **录制四个方向。** 界面依次指示左上、右上、左下、右下，每个方向只需一次：按住 L2、自然转腕、松开。录制的是大致方向，无需固定角度、力度或节奏。每步即时检查数据与动作是否有效；失败只重试当前步，也能单独替换某个参考。
4. **生成建议。** 应用依据四个方向的代表轨迹、幅度/速度差异及普通按放样本，生成方向模板和判定参数。显示哪些方向稳定、哪些易混淆；样本无法分开时明确提示补录，不强行生成“最佳阈值”。
5. **可选测试。** 用没有参与生成参数的新动作试手感，随机提示四方向，并穿插普通 L2 按放。展示正确方向、错方向、未触发、无动作误触的次数和具体原因；不要求全部正确才允许应用。结束测试保留草稿，方便继续调整。少量试次只能用于本轮自检，不能宣传为长期准确率。
6. **应用校准。** 参考齐全、可区分且参数有效时，即可点击一次“应用校准”将整组结果持久保存为个人默认。取消整个校准或离开设置保持原配置；不需要再点第二个保存按钮。

五步校准用于快速建立方向参考，不代表已验证的统计充分性。不使用“保证准确”“最佳阈值”等承诺；按同一动作切出的相邻数据帧也不能当成多个独立样本。

**测试应该让用户看懂为什么成功或失败。** 默认在设置窗口的四分区测试区显示候选点，松开 L2 后移动测试标记，不移动系统光标。每次给出有意义的结果，如“已定位到右上”“动作幅度不足”“方向不明确”“本次使用了 L2 组合键，已取消”。用户需要验证实际距离时，可主动进入“测试实际定位”，此时明确提示系统光标会跳转，并提供结束入口；窗口失焦、断连或进入原生模式时结束测试并清理待提交动作。

录制和预览测试只消费选定手柄的输入，不能同时触发它原有的快捷键或任务动作；其他手柄不得混入样本。正常运行与测试使用同一识别和取消规则，不能在测试区放宽门槛造成“测试能用，平时不能用”。实际 L2 组合操作的样本应标记为被取消的兼容性检查，不拿来拟合方向。

**当前阈值生成方式。** 对本机已有的角速度，按真实时间间隔求相对于 L2 起点的短时旋转，提取主运动幅度、速度、时长和方向；正常回弹不会覆盖主运动。每个方向录一次作为参考，后续判断更接近哪个参考，并留出方向边界；幅度和速度门槛主要依据普通按放噪声，再重放录制数据检查是否冲突。不能单凭一帧峰值或单一幅度阈值决定象限。

如果四个方向彼此重叠，或有效动作与普通晃动无法分开，应补录、调整自然动作或报告当前方式不稳定，不能只把所有阈值降低直到训练样本“全通过”。首轮可用简单方向模板与规则；没有证据需要引入复杂模型。纯平移与转腕的数据特征不同，仍须先验证实际甩动形式，不能用调参掩盖输入特征不足。

**保存与恢复的含义：**

- “个人默认”指当前用户的体感配置，下次启动继续采用，不是修改其他用户或所有控制器的内置推荐。首版可按 DualSense 家族与明确选定的配置保存，不把临时连接 ID 当成稳定的硬件身份；个人参数不因切换 Codex、Claude 等 Harness 而自动改变。
- 保存方向模板、判定参数、配置版本与适用的握持说明。一次录制得到的静止零偏不能永久视为准确，重连与后续使用仍需有效性检查。原始录制默认仅用于本轮调试，不要求上传。
- 手动调参和新录制先在测试草稿中生效，应用后才替换日常参数。参数改变后，先前测试结果标记为过期，不能继续显示为新参数的验证结果；用新动作重测，再应用。
- 提供“还原本次调整”“恢复上次校准”和“恢复内置推荐”三个含义清楚的恢复动作；只有相关状态存在时显示。恢复内置推荐不会顺便重置用户的其他按键映射。
- 依据 [DESIGN.md](../../DESIGN.md)，“立即生效的设置不加保存按钮”。此处录制与调试是未生效的整组草稿，一次“应用校准”同时提交并保存，符合现有原则。无需增加一个重复的全页保存步骤。

后续验证应使用真实录制回放与新动作，覆盖不同强度、正常回弹、慢漂、L2 按压扰动、方向边界、数据缺口、取消和恢复旧配置。判定期望来自明确的目标标签及实际操作意图，不能用同一识别算法生成期望结果后再宣称通过。

## 二、传感器实际能提供什么

DualSense 配有三轴陀螺仪和三轴加速度计。[Sony 官方规格](https://sonyinteractive.com/en/press-releases/2020/playstation-5-launches-this-november-at-399-for-ps5-digital-edition-and-499-for-ps5-with-ultra-hd-blu-ray-disc-drive/)确认硬件构成；Apple 的 [GCMotion](https://developer.apple.com/documentation/gamecontroller/gcmotion) 提供按设备能力读取的系统接口。

| 信息 | 可以用来做什么 | 不能直接推断什么 |
| --- | --- | --- |
| 角速度：手柄绕三个轴转得多快 | 相对指针移动、旋转参数、短时角度变化 | 屏幕上的绝对指向、永不漂移的朝向 |
| 总加速度：运动与重力共同形成的读数 | 运动强弱、近似静止判断，辅助估计倾斜 | 在房间中移动了几厘米、用户有意执行某条命令 |
| 重力方向与角速度融合后的估计 | 适应持握姿势、定义倾斜中立点 | 仅靠重力修正所有轴的长期朝向误差 |
| 经过分类的运动模式 | 研究特定手势、拿起放下的候选信号 | “现在要批准”“正在握持”“正在关注某个任务”等确定意图 |

**六轴传感器不等于六自由度空间定位系统。** 陀螺仪积分存在偏差积累；重力参考能帮助俯仰和横滚，但不能单独解决偏航长期漂移。加速度也受非重力运动干扰。精确三维位置和屏幕绝对瞄准还需要额外参考，不能仅凭接入 IMU 承诺。[Analog Devices 对漂移与外部参考的解释](https://www.analog.com/en/resources/analog-dialogue/raqs/raq-issue-139.html)

### 本机已验证的事实

已有独立后台 Swift 探针在当前 Mac 上进行了约 6 秒采样，没有发送键鼠事件；结束后解绑回调并恢复探针记录的初始传感器激活状态。

| 项目 | 观察结果 |
| --- | --- |
| 系统 | macOS `27.0.1 (Build 26A434)` |
| 设备 | `DualSense Wireless Controller`，Bluetooth，VID `1356` / PID `3302` |
| Motion 接口 | 存在；角速度可用；需要手动激活，初始未激活 |
| 姿态与重力分离 | `hasAttitude = false`；`hasGravityAndUserAcceleration = false`；总加速度可读 |
| 采样窗口 | 344 次回调，首末相隔 5.98355 秒，平均约 57.32 次/秒 |
| 首次总加速度 | `(0.03065, -0.21629, -0.96146)`，单位 g |
| 首次角速度 | `(0.00851, 0.00316, 0.00107)`，单位 rad/s |

这证明了**本机当前蓝牙连接的数据通路**。约 57 Hz 是短窗口的应用回调频率，不是硬件采样率或鼠标延迟。没有要求用户主动转动手柄，未验证轴向、漂移、精度、舒适度，也未覆盖 USB、长时间运行或睡眠唤醒。没有系统姿态角，仍可研究角速度驱动的相对输入；倾斜模式则需另行处理姿态估计和中立点。

## 三、体感不是一种统一的操作方式

不同映射会产生完全不同的手感，评价时必须分开。

| 交互方式 | 用户动作与结果 | 合适的任务特征 | 主要成本 |
| --- | --- | --- | --- |
| 转动控制相对位移 | 转动时移动，停止转动即停止 | 短时指示、改变光标或视角 | 手腕范围有限，需要重新摆放；点击会扰动手柄 |
| 倾斜控制持续速度 | 保持倾角就持续输出，回中才停止 | 连续导航、可见的速度调节 | 必须维护中立姿态，停下和换坐姿也需要处理 |
| 倾角对应有限位置 | 某个姿态对应一个选项或参数位置 | 有限菜单、有限范围调节 | 选项密度、舒适角度和回中范围受限 |
| 离散动作触发命令 | 识别甩动、翻转或某段运动轨迹 | 少量明确、可区分的手势 | 日常自然动作也可能相似，需要负样本验证 |
| 运动辅助状态判断 | 从运动或静止推断“可能拿起/放下” | 辅助停止、校准或提示 | 无法可靠等同于握持、注意力或确认意图 |

这些区别有真实产品依据。[reWASD](https://help.rewasd.com/how-to-remap/gyroscope.html) 明确区分 Gyro 与 Tilt；[JoyShockMapper](https://github.com/Electronicks/JoyShockMapper/blob/master/README.md) 同时提供陀螺仪、Motion Stick、中立姿态和坐标处理。它们说明映射可以实现，不说明每一种映射都值得进入日常工作流。

## 四、既有产品给出了哪些可借鉴的经验

### 4.1 手柄工具：输入分工和模式管理已经很成熟

| 产品或项目 | 已核实的实际能力 | 对 Joy Harness 的启发 | 迁移限制 |
| --- | --- | --- | --- |
| JoyShockMapper | 自带 Windows 桌面配置，体感和摇杆控制指针，按钮执行点击/快捷键，左摇杆负责滚轮；另支持触摸门控、按住启停、自然坐标系 | 体感可以只是输入组合的一部分；停用、复位与其他输入共存同样重要 | 官方材料主要覆盖 Windows/Linux，没有确认 macOS 支持，也没有桌面效率对照数据 |
| reWASD | Gyro 停转即停；Tilt 保持倾角持续输出；可重设中立点和改变模式 | 必须明确动作的含义；用户换坐姿后仍需可理解的基准 | Windows 产品，主要示例为游戏相机和赛车，不能当成阅读办公的收益证明 |
| Steam Input | 按住切换模式、松开恢复；提供抖动平滑和扣扳机时的鼠标移动抑制设置 | 明确退出语义；考虑按键受力引起的运动 | 游戏输入映射不等于 macOS 桌面 API；平滑、阈值与响应性有取舍 |

来源：[JSM 桌面配置](https://github.com/Electronicks/JoyShockMapper/blob/master/dist/GyroConfigs/Desktop.txt)、[JSM 配套指针配置](https://github.com/Electronicks/JoyShockMapper/blob/master/dist/GyroConfigs/_2Dmouse.txt)、[reWASD 官方说明](https://help.rewasd.com/how-to-remap/gyroscope.html)、[Valve 模式切换](https://partner.steamgames.com/doc/features/steam_controller/mode_shifting)、[Valve 输入模式](https://partner.steamgames.com/doc/features/steam_controller/input_source_modes)。

两处容易误读的边界：JSM 现成桌面配置的滚轮来自**摇杆**；Valve 支持矩阵中的 Gyro → Scroll Wheel 单元格为空。因此，上述手柄工具资料尚未证明现成的体感滚轮配置。JSM 源码存在 Motion Stick 与滚轮模式的组合路径，也只能证明可组合性。下文 Spotlight 则提供了运动滚动的真实产品先例，但仍不能证明它优于 Joy Harness 现有右摇杆。

### 4.2 非游戏产品：体感往往服务于交流或特定输入困难

**Logitech Spotlight：指示与临时调节。** 初代官方规格列出加速度计和陀螺仪；数字高亮、放大和指示帮助听众理解演讲者说的对象。它还支持按住按钮并上下移动来调音量或滚动。价值在于离开电脑后仍能讲清楚、短暂调节，不要求用户持续用空中光标完成精密编辑。[官方规格](https://hub.sync.logitech.com/spotlight/post/specifications---spotlight-IkhufYSFM900tAT)、[功能说明](https://www.logitech.com/en-us/shop/p/spotlight-presentation-remote.910-004860)、[运动调节说明](https://hub.sync.logitech.com/spotlight/post/adjust-volume-or-scroll-functions-with-logitech-spotlight-eEiRWprztxX9XEU)

迁移时要考虑形态：初代 Spotlight 约 49.2 g，DualSense 约 280 g，握持与受力不同；不能把单手演示器的舒适性直接复制为双手手柄结论。这里有用的是“短时、明确用途的连续动作”这一原则。

**Apple Watch AssistiveTouch：让用户不必用另一只手触屏。** 它通过手势移动焦点、选择和打开上下文菜单，也能用 Motion Pointer 倾斜手腕移动指针。握拳/捏合等识别结合 IMU、光学心率信号和机器学习，不能因为 DualSense 有 IMU 就认定它也能识别这些手指动作。可借鉴的是焦点可见、确认分离和替代输入；手表的贴肤传感、系统级焦点和小屏幕都与桌面手柄不同。[Apple 技术介绍](https://www.apple.com/sg/newsroom/2021/05/apple-previews-powerful-software-updates-designed-for-people-with-disabilities/)、[AssistiveTouch 使用说明](https://support.apple.com/en-ie/111111)

**SpaceMouse：连续视角控制与内容编辑分工。** 用户推拉、扭转控制帽来平移、缩放和旋转视图，另一只手用普通鼠标选择、编辑。它采用光学微位移测量和稳定桌面基座，并非手持 IMU 空间追踪。启发是给第二种输入明确职责；限制是 DualSense 没有同样的机械回中、桌面支撑和 CAD 集成，不能宣称能直接取代 SpaceMouse。[产品说明](https://3dconnexion.com/us/product/spacemouse-pro/)、[传感技术说明](https://3dconnexion.com/au/about-us/)

这些产品支持一个共同的设计判断：**先确定运动在当前任务中表达什么，再决定如何识别它。** “用了运动传感器”不是独立的用户收益。

## 五、人因研究是否支持“更快、更准、更轻松”

### 5.1 最接近本场景的直接比较

Ramcharitar 与 Teather 的 2017 年探索研究，让 **5 人坐在沙发上面对 27 英寸电视**，使用 Steam Controller 的摇杆、触控板、陀螺仪及鼠标完成标准目标点选。已核对作者公开全文。

| 输入方式 | 论文报告的平均吞吐量 |
| --- | ---: |
| 鼠标 | 4.73 bits/s |
| 手柄触控板 | 2.98 bits/s |
| 手柄陀螺仪 | 2.85 bits/s |
| 手柄摇杆 | 2.39 bits/s |

吞吐量综合定位速度与落点分散程度，不是每秒点击数。该样本均值中，体感好于摇杆，与触控板接近，鼠标最好。**这支持把体感列为比较对象，不支持它天然优于触控板。**

边界很重要：只有 5 人；陀螺仪横向使用方向盘式滚转；肩部扳机点击；没有测试 DualSense、摇杆加体感组合、按住门控、拖拽或真实办公。本文仅采用实验条件及均值趋势，不作统计显著性或等效性外推，也不把吞吐量差转换为日常工作效率百分比。[论文全文](https://www.csit.carleton.ca/~rteather/pdfs/CHI2017_fitts_game_controllers.pdf)

### 5.2 其他研究补充了哪些限制

| 研究 | 核实范围与发现 | 对本项目可以采用的判断 |
| --- | --- | --- |
| MacKenzie & Jusoh，2001，远程指向设备比较 | 已读全文；12 人，空中气鼠与桌面鼠标表现不同，但站/坐姿和观看距离也不同 | 自由持握输入必须单独评价，不能把气鼠或桌面鼠标结果直接套给 DualSense |
| Hincapié-Ramos 等，2014，Consumed Endurance | 已读作者摘要；研究悬空上肢负荷及其与主观用力评分的关系 | 评价应包含姿势和疲劳；不能把大幅抬臂研究当作有扶手支撑的手腕微动结论 |
| Kerber 等，2015，WristRotate | 已读 DFKI 摘要；研究如何从日常运动中区分有意手势，使用大量日常记录 | 手势测试需要拿起、放下、说话、换姿势等非命令样本，不能只测预定手势 |
| Oakley & O’Modhrain，2005，Tilt to Scroll | 已读作者机构摘要；姿态映射有限列表位置及振动反馈有正面结果 | 不能推导“保持倾角持续滚网页”优于右摇杆；位置映射与速度映射、菜单与长文是不同任务 |

来源：[远程指向全文](https://www.yorku.ca/mack/ehci01.html)、[疲劳研究摘要](https://hci.cs.umanitoba.ca/publications/details/consumed-endurance-a-metric-to-quantify-arm-fatigue-of-mid-air-interactions)、[WristRotate 摘要](https://www.dfki.de/en/web/research/projects-and-publications/publication/8163)、[倾斜列表研究摘要](https://pure.kaist.ac.kr/en/publications/tilt-to-scroll-evaluating-a-motion-based-vibrotactile-mobile-inte/)。未取得全文的研究不补写样本人数、误触率或效应量。

**本次找到的研究，没有直接回答 DualSense 能否改善 Joy Harness 的长期日常使用。** 它们足以约束产品承诺，但不能代替目标用户的任务比较。

## 六、放到 Joy Harness 里，各类用途的价值判断

当前产品已经提供左摇杆指针、右摇杆滚动、触控板精细移动、按键映射、Harness 切换、语音触发与六槽控制。新增体感必须对照这些能力，而不是对照“完全没有手柄控制”的情况。[现有映射](../controller-mappings.md)、[领域边界](../../CONTEXT.md)

| 用途 | 可能增加的价值 | 现有替代与实际缺口 | 本报告判断 |
| --- | --- | --- | --- |
| L2 斜向甩动、松开定位到象限中心 | 用一次动作完成大范围粗定位，再用已有输入微调 | 已明确反馈远距离移动慢；需验证方向识别和 L2 共存规则 | 已有开发版，并按录制过严的反馈简化；尚未测量日常效率 |
| 通用体感鼠标 | 离桌指向，多一种运动控制方式 | 已有触控板与摇杆；缺少增量收益证据 | 可作输入对照基线，暂不作为主要卖点 |
| 语音搭配可见目标或选区 | 减少向 AI 描述“哪里、哪个”的负担 | 摇杆/触控板也能指示；缺对象、截图、语音与目标应用的上下文传递 | 与智能体场景最相关的研究方向，但价值不全来自体感 |
| 演示高亮、临时指示 | 讲解时让自己或他人清楚看到正在谈论的区域 | 普通鼠标可能缺可见强调；需要独立指示层及验证共享可见性 | 有直接相邻产品先例；适合作为讨论场景，不足以改变当前产品主线 |
| 临时缩放、调范围、定位时间 | 不移动手指也能调整另一个连续维度 | 摇杆也可调节；目标应用需要有明确参数和稳定控制入口 | 条件成立时有研究价值，限制为少量可预览、可回退的参数 |
| 倾斜长文滚动 | 保持姿态即可持续浏览 | 右摇杆已经统一滚动；还要承担中立姿态和停下成本 | 当前增量价值偏弱，不建议优先 |
| 3D 模型或大画布操作 | 转动手柄与视角旋转可能有直观对应 | 当前并非 CAD/3D 工具；需要应用适配，不能提供精确位置跟踪 | 作为专用 Harness 扩展方向，不纳入通用默认 |
| 翻转、甩动切会话或窗口 | 增加少量快捷入口 | 肩键与 PS 浮层已有入口；增加学习和自然运动误判 | 当前不推荐优先；若研究，只用于可见、可撤回的低影响操作 |
| 拿起/放下自动处理 | 辅助停止体感、静止校准或提示准备状态 | 静止不等于放下，拿起不等于要操作 | 可作辅助手段，不能单独决定激活应用、录音、发送或批准 |
| 特定用户的替代输入 | 对某些不便精细操作拇指的人增加选择 | 手腕运动对另一些人反而困难 | 需要针对实际用户验证，不能笼统宣传为更无障碍或更省力 |

这个排序是研究判断，不是让用户从功能菜单中选一个。现阶段没有足够证据给它们分配开发日期或收益百分比。

## 七、怎样融入日常操作才有意义

### 7.1 把“这里”变成 AI 确实收到的对象

一个有针对性的情境：用户查看 AI 生成的网页，指示某张卡片说“这里的留白缩小一点”；或者查看输出，圈定一段内容说“解释这一段”。理想流程是：

1. 进入明确的讨论状态，屏幕显示指示点或选区。
2. 用户定位目标，目标锁定后可放松手腕。
3. 用户继续说话，界面明确显示即将提交的区域或对象。
4. 明确提交后，目标与语音内容一起交给正确的 Harness；取消则结束。

语音结合指向有长期的一手研究基础。MIT 的 Put That There 用自然语言与手势共同操作图形对象；Microsoft Research 的客厅电视浏览研究也融合语音和指向来理解意图与参数。两者支持“指向补充语言指代”这一原则，不能证明 DualSense 优于其他指向设备。[MIT 项目介绍](https://www.media.mit.edu/publications/put-that-there-voice-and-gesture-at-the-graphics-interface/)、[MSR 研究摘要](https://www.microsoft.com/en-us/research/publication/multimodal-conversational-search-and-browse/)

**Joy Harness 当前缺的不是仅仅一条体感回调。** 现有语音触发只启动既有语音入口，截图动作只是发送快捷键；没有通用的“把当前指向对象与语音绑定后提交”链路。像素选区也不等于源代码行或应用对象身份。要实现上述体验，需要明确的截图/选区获取、语音关联、预览和目标应用接入。

因此，这更适合作为一项独立的“离键盘讨论对象”产品研究。体感只是其中一种定位方式；如果触控板同样好用，应保留它，不能为了使用传感器强制换输入。

### 7.2 只在当前任务里多提供一个连续维度

例如用户正在讨论一个图表，需要临时放大；正在选截图，需要微调范围；正在看执行录屏，需要前后定位。此时小幅转动可以表达参数变化，按键仍负责确认和取消。

这种用法成立要同时满足三个条件：参数清楚可见、调整能够撤回、目标应用提供稳定入口。缩放倍率、选区范围、时间位置有连续意义；模型选择、任务切换和权限批准通常是离散决定，不适合为了体感而改造成角度旋钮。

它的评价重点是能否减少切换控制器或反复按键，而不是“支持几轴”。现有右摇杆已经很好地表达滚动，因此单纯再增加倾斜滚动的理由较弱。

### 7.3 让阅读和等待保持安静

真实的智能体工作循环包含长时间阅读、思考、说话和等待。人会换坐姿、把手柄放到腿上、挪一下位置。体感应在明确的操作状态里才影响界面，状态外的自然运动不能变成命令。

可以研究静止样本辅助校准、异常时停止连续输出，但“用户不动了”“手柄倾斜了”都不足以判断已确认或已结束讲话。任务是否完成、用户是否关注，也不能从手柄姿态推断；这些应继续由现有工作流和明确操作提供。

## 八、日常可用需要哪些交互条件

1. **进入、退出和暂停有明确含义。** 按住、触摸或显式模式都能作为边界，但本报告不预占具体键位；当前 L1/R1、L2/R2、Options、PS 等已有用途。增加一个必须一直按着的键本身也是成本。
2. **可以放松手腕并继续。** 有限转动范围需要暂停、重新摆放或重设中立点；不能要求一直对准某个固定姿势。静止偏差、中立姿态和坐标方向是三个不同问题。
3. **运动、预览与执行分工清楚。** 指示目标不自动点击，调整选区不自动发送，停住或放下不自动批准。普通应用未必支持通用预览层，需逐项定义动作。
4. **保留替代输入。** 体感是可关闭的选项，原有按钮、摇杆和触控板仍可完成相关操作；不同运动能力的用户需要不同路径。W3C 的 Motion Actuation 与面向非网页软件的解释也支持这一原则。[WCAG 2.5.4](https://www.w3.org/WAI/WCAG22/Understanding/motion-actuation.html)、[WCAG2ICT](https://www.w3.org/TR/wcag2ict-22/#applying-sc-2-5-4-motion-actuation-to-non-web-documents-and-software)
5. **融入现有状态管理。** 原生手柄模式、Harness 浮层、断连、数据中断和改映射时停止输出；恢复后不补发旧位移。多手柄的运动、启用和校准逐设备隔离。界面遵守已有 [DESIGN.md](../../DESIGN.md)，日常只表达目标和可用状态，不常驻六轴图表。

## 九、投入建议与验证方法

**优先验证维护者已明确提出的 L2 四象限定位。** 这条需求有具体痛点和可观察结果，应直接围绕它比较原有远距离移动流程。通用体感鼠标仍不宜仅凭接口可用而作为默认能力；“离键盘时表达对象”和“任务中的短时连续调节”保留为进一步研究方向。

若后续投入验证，应把两类收益分开：

| 要回答的问题 | 应采用的比较 | 记录什么 |
| --- | --- | --- |
| 加上目标上下文是否改善与 AI 交流 | 纯语音，对比带可见选区/对象的语音；先保持定位方式一致 | 指错对象、补充解释次数、完成任务所需步骤 |
| 体感本身是否提供额外收益 | 在同一目标传递流程中比较摇杆、触控板、体感 | 定位时间、误点/重试、拿回鼠标次数、学习成本 |
| 连续调节是否更顺手 | 同一参数分别用既有控件和体感调整 | 达到目标时间、过冲、撤回、姿势负担 |
| 能否融入真实工作节奏 | 包含阅读、说话、换姿势、拿起放下的连续任务 | 非预期输出、模式误用、疲劳、是否愿意持续使用 |

练习时间和试验顺序需平衡，不能只看第一次的新鲜感。USB/蓝牙、不同坐姿、睡眠唤醒与多设备要分别验证。若改善来自“传递了目标上下文”，而体感本身没有增益，应投入上下文链路；若只对部分用户有帮助，可作为可选输入保留。若需要牺牲常用按键却没有稳定收益，就没有必要发布。

当前尚无本产品的基线，不设未经论证的效率门槛，也不把其他设备论文中的均值当作本产品指标。是否值得继续，应由实际任务成本、错误与舒适度共同决定。
